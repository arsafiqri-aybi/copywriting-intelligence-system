# Project Contract — Copywriting Intelligence System

## Primary mission

Build a research-grounded, evidence-aware neural knowledge architecture and executable reasoning system for world-class copywriting.

The objective is not a formula/template library. The objective is to model the mechanisms that make communication work, connect those mechanisms into an evidence-grounded reasoning network, convert that network into an operational copywriting intelligence system, and ultimately package the validated system into a reusable AI Skill.

### Scale

Design the smallest architecture that can reliably produce the accepted result.

For every material execution node preserve:

- dependencies;
- expected output;
- criticality;
- capability floor;
- tools;
- context needs;
- verifier;
- pass condition;
- escalation trigger.

Verification is part of architecture.

### Governor

Optimize reasoning effort, context, retrieval, research depth, tools, reuse, retries, verification and coordination while preserving all protected constraints and mandatory gates.

Diagnose bottlenecks before escalating resources.

### Skill Builder

Use only after the knowledge architecture and reasoning system are sufficiently validated. Do not begin the project by writing a giant `SKILL.md`.

### GitHub

GitHub is the authoritative persistent project state. Preserve accepted upstream artifacts. When upstream knowledge changes, invalidate only affected descendants.

## Protected constraints

1. Exactly seven top-level psychological/communication cores are protected in Architecture v1.
2. The cores are a network, not a mandatory linear funnel.
3. Market & Value is an outer system, not an eighth psychological core.
4. Research, Evidence & Feedback is the epistemic substrate, not an appendix.
5. Scientific claims must preserve provenance and uncertainty.
6. Correlation, prediction, mechanism and causation must remain distinguishable.
7. Null and contradictory evidence must not be silently removed.
8. Metrics/proxies must not be treated as direct mental-state measurements without validity evidence.
9. Graph connectivity must not be forced.
10. Architecture/runtime weights must not be mislabeled as empirical effect sizes.
11. Knowledge quantity is not a quality metric.
12. Project completion requires evidence that mandatory gates pass.

Use breadth-first coverage before depth-first perfection during the knowledge build. Do not perfect one core while other required cores remain empty.

## Completion definition

`PROJECT_COMPLETE` requires:

- required architecture artifacts exist;
- seven cores have accepted coverage;
- critical edges have been audited;
- provenance is preserved;
- critical contradictions are resolved or bounded;
- reasoning engine functions;
- measurement layer functions;
- feedback loop functions;
- copy runtime functions;
- representative evaluations pass;
- holdout evaluations pass;
- adversarial critical failures are absent;
- Skill runtime is validated;
- every mandatory quality gate is PASS.

Otherwise use accurate statuses such as `BLOCKED`, `REPLAN_REQUIRED`, `UNDER_RESEARCH`, or `INCOMPLETE`.
