# Research Plan

## S1 — Domain Taxonomy

For each of the seven cores:

1. map relevant disciplines/subdisciplines;
2. identify canonical construct families;
3. collect aliases and terminology collisions;
4. identify competing theories;
5. map measurement traditions;
6. identify likely overlaps with other cores;
7. create candidate modules/neurons without premature acceptance.

Deliverables:

- domain map;
- construct registry;
- terminology collision registry;
- theory map;
- measurement-tradition map;
- open-gap register.

## S2 — Research Foundation

Build or adapt:

- source registry;
- atomic-claim registry;
- contradiction registry;
- uncertainty registry;
- measurement mappings;
- node schema;
- edge schema;
- research lifecycle and promotion rules.

## S3 — Seven-Core Knowledge Build

Use breadth-first completion.

For every module:

```text
scope
→ constructs
→ candidate neurons
→ atomic claims
→ evidence
→ boundaries
→ measurements
→ copywriting implications
→ lifecycle decision
```

Do not overdevelop one core while other required cores remain uncovered.

## S4 — Connection Build

Audit all 21 unordered core pairs.

For each pair:

- search for mechanism-level relationships;
- identify mediation/moderation;
- identify inhibition/competition;
- identify bidirectionality;
- identify feedback loops;
- preserve non-edges;
- record insufficient evidence.

Then deepen important module/neuron-level connections.

## S5 — Market & Value Integration

Map real-world commercial inputs to core mechanisms without rewriting psychological constructs into marketing jargon.

## S6 — Reasoning Engine

Requirements:

- context ingestion;
- targeted retrieval;
- mechanism activation;
- cross-core synthesis;
- conflict handling;
- uncertainty propagation;
- evidence warnings;
- strategy synthesis;
- copy generation;
- critique/diagnosis.

## S7 — Measurement, Experiment & Feedback

Separate latent mechanisms from observable signals.

Support:

- direct behavior;
- validated instruments;
- behavioral tasks;
- classifiers;
- platform proxies;
- self-report proxies.

Every proxy mapping must document ambiguity and alternative explanations.

## S8 — Evaluation

Maintain separate:

- development set;
- regression set;
- holdout set;
- adversarial set.

Evaluate across:

- channels;
- products/categories;
- audience sophistication;
- awareness states;
- weak/conflicting evidence;
- ambiguous briefs;
- brand constraints;
- factual constraints;
- ethical/truthfulness constraints.

Do not tune directly against clean holdout cases.

## S9 — Skill Runtime

Only after sufficient validation, package with progressive disclosure:

```text
SKILL.md
references/
knowledge/
scripts/
schemas/
evaluation/
assets/
agents/
```

The runtime Skill should retrieve the knowledge architecture rather than embed the whole research library into one instruction file.

## S10 — Continuous Research

New evidence enters through controlled lifecycle:

```text
candidate source
→ extraction
→ verification
→ contradiction/boundary check
→ promotion decision
→ dependency invalidation
→ targeted regression
→ versioned release
```
